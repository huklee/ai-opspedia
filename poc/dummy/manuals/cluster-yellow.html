검색 클러스터 yellow 상태 대응

문서 ID RB-SRCH-002 · 담당 검색 인프라팀 · 최종 검토 2026-09-10 · Confluence 내보내기 문서

es-prod 클러스터 health 가 yellow(레플리카 미할당)일 때의 확인·조치 절차. yellow 는 검색 서비스는 가능하지만 노드 장애 시 데이터 손실 위험이 있는 상태.

1. 심각도

상태심각도조치 시한
yellow, 새 인덱스 레플리카만 미할당SEV3당일
yellow, 서비스 중 alias 대상 인덱스 레플리카 미할당SEV21시간
red (프라이머리 미할당)SEV1즉시

2. 확인

  1. GET _cluster/health?level=indices 로 yellow 인덱스 목록 확인
  2. GET _cat/shards?v&h=index,shard,prirep,state,unassigned.reason | grep UNASSIGNED
  3. GET _cluster/allocation/explain 으로 미할당 이유 확인
  4. 새로 만든 인덱스(예: products_v42)의 number_of_replicas 가 데이터 노드 수 - 1 을 넘는지 확인
  5. 디스크 사용률: GET _cat/allocation?v (high watermark 90 %)

3. 원인별 조치

미할당 이유조치
DISK_THRESHOLD (워터마크 초과)오래된 인덱스(alias 없는 이전 버전 2개 초과분) 삭제 또는 노드 추가
레플리카 수 과다PUT products_v42/_settings {"number_of_replicas": 1}
NODE_LEFT (노드 이탈)노드 복구 대기 5분 → 미복구 시 인프라팀 호출
ALLOCATION_FAILED (재시도 초과)POST _cluster/reroute?retry_failed=true

4. 검증

GET _cluster/health → status green, unassigned_shards 0. alias 전환 대기 중이면 상품 인덱스 alias 전환 · 롤백 런북 진행.

5. 에스컬레이션

red 전환 또는 30분 내 미해결 시 검색 인프라팀 리드 · 인프라 온콜 호출.
